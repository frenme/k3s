# AGENTS.md of app/

Rules for the Go services. Paths are relative to `app/`; `make` commands run from the repository root. Infrastructure: `infra/AGENTS.md`.

## Layout

- `cmd/<service>` entrypoint, `internal/<service>` the service, `internal/clients/<service>` HTTP clients of other services, `internal/lib` shared code (`app`, `httpx`, `pg`, `cache`, `lock`, `pagination`, `idempotency`, `envconfig`).
- `openapi/*.yaml` and `internal/gateway/policy/rules_gen.go`, `internal/gateway/docs/openapi_gen.json` are generated by `make openapi`, never edited by hand. CI fails when they are stale.
- New service: the `cmd` and `internal` folders, then the infra steps in `README.md`.

## A service

`internal/users` is the reference:

```
internal/<service>/
  model/       plain structs, one file per model, all errors of the service in errors.go
  storage/     all database access (GORM), one file per table, migrations/
  <feature>/   one package per resource
    service.go business logic, no HTTP and no SQL
    v1/        dto.go (request and response structs) and handler.go (Huma operations)
  routes.go    Setup wires features; OpenAPI builds the spec without a database
```

- Order in a Go file: `const` and `var`, types each followed by `NewX` and its methods, then free functions.
- Features never import each other; what they share lives in `model/` and `storage/`.
- Services never import another service's `internal/<service>` (depguard enforces it): they call each other over HTTP through `internal/clients/<service>`.
- Each service owns one Postgres schema and one migration history.

## HTTP

- Huma on `net/http`. Public routes `/v1/<resource>` on `:8080` (reached as `/api/v1/<service>/...` through the gateway), internal routes `/internal/v1/<resource>` on `:8081` (other services only; the gateway refuses any `internal` path). A breaking change goes to a new `v2/` folder.
- Errors are `httpx.Error{Status, Code, Message}`, declared in the service's `model/errors.go` (shared ones in `internal/lib/httpx/errors.go`). Storage and services return them as they are; check with `errors.Is`. Handlers just `return nil, err`: `httpx.Register` turns unknown errors into `internal_error`, logs 5xx and never leaks details. Clients branch on `code`, not on `message`.
- Validation lives in DTO tags, not in services. Wrong input is always 400.
- Status codes: 200 for every success, 400, 401, 403, 404, 409, 413, 502, 503, 504. No 201, 204, 405 or 422. A resource of another user is 404, never 403.
- The current user comes only from `httpx.CurrentUser(ctx)` (`X-User-ID` set by the gateway), never from a body or a query.
- Environment variables only through `envconfig.Load[EnvConfig]()`.
- Lists use keyset pagination (`pagination.Params`, `pagination.Page[T]`, `pg.Keyset`). Retry-safe endpoints take `Idempotency-Key` (`idempotency.New`).
- Calling another service: `internal/clients/<service>` over `httpx.ServiceClient`, one line per route, a struct with only the fields the caller needs.

## Database

- Only `storage/` touches the database, through `*pg.DB` (`Write`, `pg.Read` for reads that prefer the replica). GORM rows stay private in `storage/` and are mapped to `model/`. A non-UUID id is answered as not found by `pg.IsUUID`, never sent to Postgres.
- Several steps atomically: the service declares `transactor` (`Do(ctx, func(ctx) error) error`, satisfied by `*pg.DB`) and wraps the storage calls; do HTTP calls to other services before `Do`.
- Migrations are SQL files `storage/migrations/<yyyymmddhhmmss>_<name>.sql`, never `AutoMigrate`. They must work with the previous release: add first, switch the code in the next release, drop last. `CREATE INDEX CONCURRENTLY` goes to its own `*.notx.sql` file with one statement.
- Services connect through PgBouncer in transaction mode: never rely on session state (`SET`, advisory locks, `LISTEN`) in storage code. Migrations use `DATABASE_DIRECT_URL`.
- `admin` reads other services only through views they own (`users.admin_users`, `orders.admin_orders`): change the view before dropping or retyping a column it uses.

## Gateway

`internal/gateway` is a pipeline wired in `setup.go`: `edge` (client IP, CORS, body limit), `policy` (rule of the request), `auth` (JWT, roles), `validate` (rejects requests that break the OpenAPI spec), `cache` (public GETs, in memory), `proxy` (timeout, circuit breaker, retries of GET), `docs`.

- Policy lives next to the handler: `httpx.Register(api, op, httpx.AccessPublic|AccessUser|AccessAdmin, handler, options...)` with `WithTimeout`, `WithMaxBody`, `WithCache`. `make openapi` turns it into the generated gateway files. An operation without access fails the generator.
- Non-public routes need `Authorization: Bearer <jwt>` (key from `JWT_SECRET`, `JWT_PUBLIC_KEY` or `JWT_JWKS_URL`; `exp` and `sub` required). Nothing here issues tokens.
- Roles live in `users` (`user` for everyone, `admin` granted explicitly). `/api/v1/admin/**` always needs the admin role. The gateway strips `Authorization` and any client `X-User-ID` and `X-User-Roles`, then sets `X-User-ID`; services trust it only because the NetworkPolicy lets nothing but the gateway reach `:8080`.
- Rate limits per route are not in Go: `infra/deploy/values/base/gateway.yaml` (Traefik).

## Other services

- `common`: runtime settings (`appconfig`, cached in redis) and `/api/v1/common/health` (public `ok`/`unhealthy`; `/health/details` needs the admin role). Every service may depend on it.
- `admin`: one pod, read-only access to every schema (`readAllSchemas`).
- `scheduler`: cron jobs in `internal/scheduler/jobs/catalog.go`, several replicas, a redis lock makes one replica run a tick; internal routes only, reached through `admin`.

## Telemetry

- JSON logs with `trace_id` and `span_id`; the `X-Request-ID` header equals the trace id. Secrets and tokens are masked before logs reach Loki.
- Incoming HTTP, outgoing calls made with `httpx.NewClient` (they retry idempotent requests twice), Postgres and redis are traced automatically; business logic needs your own spans.
- Business counters live next to the code that changes state (`promauto`).

## Rules

- No comments in code, golangci-lint clean.
- Before handing over: `make lint test test-integration openapi`, and `make up e2e` when a service changed.
- Never print or copy secrets, connection strings or tokens.
