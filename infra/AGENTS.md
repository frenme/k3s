# AGENTS.md of infra/

Rules for the infrastructure and for investigating the clusters. Paths are relative to `infra/`; `make` runs from the repository root. The services: `app/AGENTS.md`.

## Layout

- `deploy/helmfile.yaml.gotmpl` every release; `deploy/environments/{common,local,dev,prod}.yaml` settings (`common.yaml` has the `apps` registry and the defaults, an env file only what differs); `deploy/values/{base,derived}` values of vendor charts and of the Postgres and Redis charts; `deploy/helm/*` own charts. What differs per env for a release (sizes, retention) is `releaseValues.<release>` in the env file.
- `terraform` Hetzner servers, `k3d` the local cluster.

| ENV | kube context | namespace |
|---|---|---|
| local | `k3d-k3s-base` | `app` |
| dev | `k3s-dev` | `app-dev` |
| prod | `k3s-prod` | `app-prod` |

Platform namespaces: `monitoring`, `cnpg-system`, `cert-manager` (only with `backups: true`), `kube-system`, `cattle-system`.

## Servers

- `terraform/envs/<env>.tfvars`: `server` is the core (control plane, databases, services), `nodes` is a map of extra servers with `location`, `server_type` and `role` (`edge` by default, `core` for more capacity). `make infra-apply ENV=<env>`.
- Nodes are labeled `role=core` or `role=edge`. Edges carry the taint `role=edge:NoSchedule`: only Traefik, the gateway (a DaemonSet) and DaemonSets that tolerate everything run there; everything else lands on core.
- `edge = true` inside `server` with no `nodes`: one server for everything, labeled `role=edge` without the taint, with the web firewall. Terraform refuses a setup with no edge.
- Core servers are protected from deletion: set `protected = false` in the tfvars and apply before `make infra-destroy`. `server.backups = true` adds Hetzner snapshots.
- Security: edges join with a separate agent token; Secrets are encrypted in etcd; SSH (22) accepts keys only and is open to the world; the API (6443) is open too unless `api_sources` in the tfvars lists who may reach it (the nodes always may). Pods of the services cannot reach the metadata address `169.254.169.254` (egress policy `<service>-egress`), because the cloud-init `user_data` there holds the k3s tokens.
- The Terraform state is local (`.gitignore`d) and holds the tokens, S3 keys and registry password: back it up somewhere private.
- One environment per cluster: a second one on the same cluster shares and can delete the platform releases. Terraform for different environments must not run at the same time (one workspace per directory). An SSH key another environment already uploaded is reused (Hetzner refuses the same key twice).
- `make init` (`scripts/init.sh`) is the one-time setup: age key (`~/Library/Application Support/sops/age/keys.txt` on macOS, else `~/.config/sops/age/keys.txt`, or `SOPS_AGE_KEY_FILE`), the recipient in `.sops.yaml`, `domain` in `common.yaml`, the SSH key placeholder in the tfvars. Safe to run again; `.sops.yaml` changes only after a yes (or `YES=1`).
- `make secrets ENV=<env>` writes `dbSecret`, `redis`, `jwt`, `grafana` and encrypts the file; it never overwrites one without `FORCE=1`. `make bootstrap` = `infra-apply`, `kubeconfig`, `wait-nodes`, `deploy`; images first from `make push`.
- `make install-host` (`scripts/install-host.sh`) installs k3s on an existing Ubuntu with the cloud-init config; no firewalls. Terraform outputs: `server_ip` and `node_count` feed the Makefile, `node_ips` is for your DNS.
- The agent token and the edge taint come from cloud-init, so they reach only servers created after the change; on an existing one edit `/etc/rancher/k3s/config.yaml` by hand.
- `make lint` also runs `scripts/check-k3s.sh`: the k3s config of `terraform/templates/*.tftpl` and `scripts/install-host.sh` must stay the same; change both.

## Defaults

- Postgres: one instance, no replica; PgBouncer is always in front (`DATABASE_URL` through it, migrations use `DATABASE_DIRECT_URL`). A replica is a `core` node plus `postgres.instances: 2`; its failover needs the Kubernetes API on the core server. `make db-status` cannot reach an instance on another node than the API server (NetworkPolicy): use `kubectl get clusters.postgresql.cnpg.io -n <ns> postgres -o yaml`.
- `backups: false`. `true` turns on etcd snapshots to S3 (`s3` section, keys in the secrets), the barman plugin, WAL archiving and a daily Postgres backup. After a restore change `postgres.backupServerName`. The S3 endpoint needs a publicly trusted certificate (the chart has no custom CA option).
- No certificates in the cluster: HTTPS is Cloudflare's (SSL mode Full), the edge answers with Traefik's default certificate, no HTTP to HTTPS redirect.
- Host of an env: `<subdomain>.<domain>`; `domain` in `common.yaml`, `subdomain` in the env file, none for local.
- Dev and prod expect Cloudflare: Traefik and the gateway (`EXTRA_TRUSTED_PROXIES`) trust `X-Forwarded-For` from `environments/cloudflare.yaml` (IPv4, generated by `make cloudflare-ips`, never edit by hand), so rate limits and `client_ip` are the visitor. Ports 80 and 443 are open to everyone; `cloudflareOnly: true` opens them only to those ranges.
- `CORS_ORIGINS` of the gateway may contain `{domain}`, replaced by `domain` of `common.yaml`.
- `telemetry.metrics`, `telemetry.traces`, `telemetry.retention` (`metrics`, `logs`, `traces`) are the only monitoring switches; `dev` runs with metrics and traces off: services, Loki, Alloy and a plain Grafana with Loki only.
- Disks: Prometheus stops at `retentionSize`; Loki and Tempo have only time retention, so size their volumes by hand (prod: 20Gi each). A StatefulSet volume cannot be resized by `helm upgrade`: set it before the first deploy.
- `autoUpdates` (prod only) installs kured (reboots after OS updates, 02:00-05:00 UTC) and system-upgrade-controller (k3s to `k3sVersion`, Sundays). On a single server a reboot is an outage.

## Service registry

- `deploy/environments/common.yaml` `apps`: one entry per service. Every app except the gateway gets a database (own schema and role), redis and a public route `/api/v1/<name>`, so a typical service is `<name>: {}`.
- Keys and types are in `deploy/environments/apps.schema.json`; Helmfile rejects an unknown key or a non-boolean flag. A new flag goes to that file first. Special keys: `gateway`, `readAllSchemas` (admin), `healthCheck` (`common`), `values` (chart values, merged over `appDefaults` and the env's `apps.<name>.values`).
- Derived in `values/derived/app.yaml.gotmpl`: database and redis settings, `ROUTES`, `HEALTH_TARGETS` and the NetworkPolicy (`:8080` only from the gateway and the `healthCheck` app, `:8081` from every pod labeled `app.kubernetes.io/part-of: app`).
- The database password of a service is `sha256sum(secrets.dbSecret + "/" + <name>)` (`values/derived/app.yaml.gotmpl`, `postgres.yaml.gotmpl`), no per-service secret. Changing `dbSecret` changes every password: CNPG updates the roles, pods roll on the secret checksum, expect a short burst of auth errors.
- A new service needs only its registry line and, for its own rate limit, a route in `apps.gateway.values.ingress.routes`. CI `images` and `scan` loop over `app/cmd`.
- `values/base/<release>.yaml` is for vendor charts; a missing file is ignored on purpose.

## Connecting

Read-only kubectl and Grafana MCP:

```bash
make agent-kubeconfig ENV=prod
export KUBECONFIG=$PWD/kubeconfig-agent-prod.yaml
```

```json
{"mcpServers": {"grafana-prod": {"command": "make", "args": ["-s", "-C", "/path/to/k3s", "mcp", "ENV=prod"]}}}
```

The `agent` ServiceAccount has `view` plus read access to nodes, volumes, metrics and the CloudNativePG, Prometheus, Traefik and upgrade resources; no Secrets, exec, port-forward or changes. The MCP server is read-only and needs the operator kubeconfig and Docker.

## Queries

Loki labels: `namespace`, `pod`, `container`, `app`, `node`, `stream`, `service_name`; level is `detected_level`. Datasource uids: `prometheus`, `loki`, `tempo`.

```logql
{namespace="app-prod"} | detected_level="error"
{namespace="app-prod", app="gateway"} | json | msg="request" | duration_ms > 500
{namespace="app-prod"} |= "<trace_id>"
```

```traceql
{ resource.service.name = "orders" && status = error }
{ resource.service.name = "users" } >> { span.db.system.name = "postgresql" && duration > 100ms }
```

```promql
sum by (service) (rate(http_requests_total{namespace="app-prod", code="5xx"}[5m]))
histogram_quantile(0.99, sum by (service, le) (rate(http_request_duration_seconds_bucket{namespace="app-prod"}[5m])))
ALERTS{alertstate="firing"}
```

Investigating: firing alerts and error rate by service, then error logs (take a `trace_id`), then the failing span, then `kubectl get pods`, `describe pod`, `get events --sort-by=.lastTimestamp`, `logs --previous`, `top pods`, and the database with `kubectl get clusters.postgresql.cnpg.io -n <ns> postgres -o yaml`. Report the cause with links to the logs, the trace and the likely commit.

## Rules

- Investigation is read-only: never apply, delete, scale, restart, exec, port-forward or `make deploy` against dev or prod unless asked.
- Never print or copy secrets, connection strings or tokens, even when a log line leaks one; report the leak.
- Keep Loki queries scoped to a namespace and a short time range.
